Preparation only. Do not run final checks before 2026-10-26 00:57:50 UTC or before all admitted work has a terminal disposition. No producer, restart or new scientific check is authorized by this procedure.

1. Finish prose and scientific reviews, including T20's actual disposition if selected. Create `CLOSEOUT_EXPECTED_DISPOSITIONS.json` using apply_patch with an explicit map under `packets`: every exact T-folder name maps to `disposition` (`result`, `failure`, `resource_hold`, or `unrun`) and, for result/failure, its exact `classification`. Preserve T2 failure and T12 UNRESOLVED. A T20 technical failure or unresolved result is not a closeout failure when honestly recorded and independently reviewed. An unrun candidate must have no execution/start/terminal artifact.
2. After the cutoff and after all computations finish, run `audit_campaign.py --phase final` through SSH on academic-linux. It uses a normal shared audit lease, verifies admissions/runtime and predecessor closure, records reaping and process/affinity evidence, releases its own lease and checks the L001 lock. Save stdout to a uniquely named `INTEGRITY_FINAL_<UTC>.json` using apply_patch. No shell redirection/write trick. Inspect every issue; do not force-close, alter a parent or stop another owner's job to make it pass.
3. Complete the final prose review and resource interpretation from this snapshot. Prepare all final root status/result/report/checklist documents now, before the manifest. Explicitly state limits of historical CPU evidence. No uncomputed future test may be described as run.
4. Run `documentary_manifest.py --mode manifest --audit-file INTEGRITY_FINAL_<UTC>.json --expected-file CLOSEOUT_EXPECTED_DISPOSITIONS.json` on academic-linux. It refuses before cutoff, takes a leased core, reconciles exact named dispositions, freshly checks source/runtime/131-file parent closure, checks live campaign processes and L001 lock, and emits JSON only. Save stdout by apply_patch as `CLOSURE_MANIFEST.json` with no overwrite.
5. Independently inspect the manifest and run the same script with `--mode verify`. It rechecks evidence and requires exact file-inventory/hash equality. Save stdout by apply_patch as `CLOSURE_VERIFICATION.json`. The verifier receipt identifies the manifest hash. Neither command modifies any scientific artifact.
6. Do not change included files after manifest publication. Any unexpected extra file/hash mismatch is a real documentary issue, not permission to quietly regenerate history. Report the discrepancy and resolve via explicit new documentary versions if needed. Resource snapshots are time-bounded observations, not guarantees against future activity by other users.

The manifest includes all regular campaign files, including plans, source, result/failure evidence, logs, raw budgets, audits, review notes and these procedures/scripts. Exclusions are exactly the root `CLOSURE_MANIFEST.json`, root `CLOSURE_VERIFICATION.json`, and files whose basename ends in `.lock`. Lock files are mutable coordination artifacts; they are explicitly listed as exclusions. Unexpected symlinks are rejected for inspection rather than silently followed. No cache or scratch files are silently omitted.

The completion checklist covers scientific and scope requirements. Additional enforcement supplied here: exact named inventory (not count alone), one unambiguous terminal per executed packet, explicit unsuccessful/unrun/held cases, parent and runtime freshness, all included/excluded files, no post-manifest prose edits, and a current process/line-lock check in addition to the earlier final snapshot. This procedure does not assert complete historical aggregate CPU telemetry or independently validate unbound files outside the campaign.
