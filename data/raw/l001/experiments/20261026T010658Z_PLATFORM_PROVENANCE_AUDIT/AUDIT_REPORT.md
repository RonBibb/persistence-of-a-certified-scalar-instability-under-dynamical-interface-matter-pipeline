# L001 Mac–Linux audit: selective qualification, not a restart

## Decision

**No blanket Linux rerun is justified.** The local background and zero-mass phase supporting current Paper A/AB already have fresh Linux production. Recent AB mechanism flows also have Linux execution evidence. The principal Mac-produced numerical anchor with a missing Linux auditor receipt is the neutral all-mode kinetic bound; it exports a complete saved numerical witness, so the appropriate next step is a complete Linux exact-checker run, not another physical solve.

This is a documentary audit of sources, results, runtime receipts and checker coverage. No new scientific computation, numerical hash verification or Linux diagnostic was performed. Historical accepted results are not newly certified by this report. Independent review of this report is recorded separately.

The audit found provenance and assurance gaps, not a demonstrated Mac-induced scientific error. Linux production alone is not proof of correct arithmetic. Conversely, exact mathematics discovered or checked on Mac is not invalid merely because the host was Mac.

The constants and boxes are literally the same; the local root/common-box uniqueness argument supplies the identity of the physical background. This is stronger than nearby midpoints or overlapping outputs.

Recent bindings still name their historical parent result digests. The Oct18 route is therefore a **separate same-model/same-root assurance bridge**, not a retrospective change to the frozen parent chain. A future qualification dossier should bind that bridge explicitly. This audit has not executed a fresh comparison or rewritten historical bindings.

A charged evolving branch does not acquire a static spectral theorem merely by sharing a background at zero charge. The separate concave example has its own background and proof premises.

## Arithmetic and platform assumptions

The principal interval runtime is CPython3.12.3, GCC13.3.0 identification, Linux aarch64/glibc2.39 and python-flint0.9.0 at 768 bits/one arithmetic thread. Native maps include FLINT, GMP, MPFR and flint extensions. Python's compiler string is not the wheel's complete build attestation. Hashes establish bytes, not correct rounding or absence of native-library defects. Independent ODE sources sharing Arb are not independent arithmetic implementations.

The exact kinetic checker uses arbitrary-precision integer/Fraction arithmetic; native floating FMA and BLAS differences are not its mathematical rounding mechanism. Its checks must cover every saved cell, the initial enclosure, strict Picard tubes, recurrence/remainder bounds, event coverage and final inequality. A sample, saved flag, rationalized float or checksum would not be a substitute.

The original dyadic parameter convention is part of the model definition. Replacing it with attractive decimal rationals (for example m²=41/100) would change the model and trigger a different dependency/recomputation question. No such change is proposed.

## Minimal sufficient follow-up

1. **Qualify and run the complete kinetic Fraction checker on Linux.** Review a wrapper-only adaptation for expired deadline/output/path plumbing; freeze all witness chunks, code, interpreter and predicates; use one leased core, exact arithmetic and independent terminal review. Historical admission-to-result was about four minutes, not a measured CPU duration. A prospective 15-minute compute cap is reasonable; setup/review is additional. Passing closes the missing Linux witness layer without producing a new background.
2. **Package the explicit Oct18-to-current same-root bridge and cheap exact consequences.** Curvature/openness/stiffness historical arithmetic took roughly 0.04/0.14/0.42 s. Complete checks are seconds-scale arithmetic; allow roughly 5–15 minutes for staging/review, not a guaranteed total. Bind original and independent checkers, not only result hashes.
3. **Baseline mass: recover receipt before replay.** If stronger actual-host witnessing remains required, prospectively admit the original endpoint flows with pre/post loaded-runtime evidence. The historical complete six-flow packet took 50.88 s; this supports a few-minute compute envelope, not a promise. Do not rerun bisection, scans or every descendant without cause.
4. **Optional stricter runtime/source qualification.** Record loaded library identities/ABI and evaluate exact-input/outward-operation controls with recurrence/Picard method review. Controls are supporting evidence, not an arithmetic-library proof. Complete equation-to-polynomial checks for T17/T18 are a useful precondition to a later forced second-order solve, not authority to launch it.
   For the concave branch, include all admission/child receipts, saved endpoint predicates and independent local coefficient recurrences in a bounded checker. No end-to-end timing is measured for that proposed checker. Historical numerical precedents range from 1.246 s for integer coordinate replication to 81.324 s for an eigenvalue run and 142.628 s for a uniform leading-width run. The 33.47-minute inconclusive sixth-order cover and estimated 55.7-hour finer cover are not appropriate default platform qualifications.
5. **Fresh production and downstream recomputation only when necessary.** Trigger it if a required witness fails, an original input/model differs, or a required proof premise cannot be recovered or independently checked. Recompute only affected descendants. Preserve both old and new evidence and predeclared failure criteria. A discrepancy first needs diagnosis; it is not permission to tune the answer.

At most two aggregate Linux cores, normal shared leases/HOLDs, no change to sealed packets. Checks projected beyond an hour require qualified exact atomic resumption before launch. No new computation was admitted by this audit plan; this list is prospective.
